# QLC+ 5 — GitHub Codespaces cross-build for Raspberry Pi ARM64

This kit is intended to be **unzipped at the root of a fork of the official QLC+ repository**.

It creates an amd64 GitHub Codespace that cross-compiles QLC+ 5 for **Linux ARM64 / Raspberry Pi 5** using Debian multiarch packages and the `aarch64-linux-gnu` GCC toolchain.

## What this kit targets

- QLC+ **5** QML UI (`-Dqmlui=ON`)
- Qt **6**
- Raspberry Pi OS / Debian **64-bit ARM64**
- Raspberry Pi 5
- GitHub Codespaces running on its normal x86-64 host architecture

It intentionally does **not** handle macOS.

## Files added to your fork

- `.devcontainer/devcontainer.json`
- `.devcontainer/Dockerfile`
- `.devcontainer/post-create.sh`
- `cmake/toolchains/raspberry-pi-arm64.cmake`
- `scripts/raspi/*.sh`
- `.vscode/tasks.json`
- `.vscode/settings.json`

No existing QLC+ source file is replaced.

## Installation in your fork

1. Fork `mcallegari/qlcplus` on GitHub.
2. Create/open a Codespace for your fork.
3. Upload the ZIP from ChatGPT to the **repository root**.
4. Extract it at the repository root.

Example:

```bash
unzip qlcplus5-rpi-arm64-codespaces.zip
```

5. Commit the new environment files if you want them to remain in your fork:

```bash
git add .devcontainer .vscode cmake/toolchains scripts/raspi README-RASPBERRY-CROSSBUILD.md
git commit -m "Add Raspberry Pi ARM64 Codespaces cross-build environment"
git push
```

6. In VS Code / Codespaces run:

**Command Palette → Dev Containers: Rebuild Container**

The first rebuild installs the native build tools plus ARM64 Qt/development libraries.

## One-command build

After the container has been rebuilt:

```bash
./scripts/raspi/all.sh
```

This performs:

1. environment check
2. CMake configuration for ARM64
3. QLC+ 5 build
4. staged install/package creation

## Separate commands

```bash
./scripts/raspi/check-env.sh
./scripts/raspi/configure.sh
./scripts/raspi/build.sh
./scripts/raspi/package.sh
```

Clean everything generated by this kit:

```bash
./scripts/raspi/clean.sh
```

## VS Code tasks

Use:

**Terminal → Run Task…**

Available tasks include:

- Raspberry Pi ARM64: Check environment
- Raspberry Pi ARM64: Configure QLC+ 5
- Raspberry Pi ARM64: Build QLC+ 5
- Raspberry Pi ARM64: Package
- Raspberry Pi ARM64: Configure + Build + Package
- Raspberry Pi ARM64: Clean

`Ctrl+Shift+B` runs the ARM64 build task.

## Outputs

The build directory is:

```text
build-rpi-arm64/
```

The expected executable is normally:

```text
build-rpi-arm64/qmlui/qlcplus5
```

The build script runs `file` on it and verifies that it is an ARM64/AArch64 ELF executable.

Staged package files are written under:

```text
out/
```

The package script creates:

```text
out/qlcplus5-rpi-arm64-YYYYMMDD-HHMMSS.tar.gz
```

## Copy to Raspberry Pi

Example:

```bash
scp out/qlcplus5-rpi-arm64-*.tar.gz pi@raspberrypi.local:/tmp/
```

On the Pi, inspect the archive before installing:

```bash
tar -tzf /tmp/qlcplus5-rpi-arm64-*.tar.gz | less
```

For development, it is often simpler to copy only the binary/libraries you are changing, or install into a test prefix rather than overwriting the working QLC+ installation.

## Important compatibility note

Cross-compiling a Linux application is only half of deployment compatibility.

The Codespace container in this kit is based on **Debian 13 (Trixie)** and installs Debian ARM64 Qt6 libraries for compilation. This is a good match for a Raspberry Pi running a current 64-bit Debian 13 / Raspberry Pi OS environment.

If the Raspberry Pi runs an older OS (for example Debian 12 / Bookworm), do **not** assume the generated binaries are ABI-compatible. In that case change the devcontainer base image and target package set to match the Pi, or build natively on the Pi.

Check the Pi with:

```bash
cat /etc/os-release
uname -m
```

Expected architecture:

```text
aarch64
```

## Why this is cross-compilation, not emulation

The Codespace remains x86-64. It uses:

```text
aarch64-linux-gnu-gcc
aarch64-linux-gnu-g++
```

and ARM64 development libraries. The resulting QLC+ executable cannot be run directly in the Codespace. It must be copied to an ARM64 Linux machine (the Raspberry Pi) for runtime testing.

This is intentional: it keeps compilation substantially lighter than emulating a complete ARM64 desktop.

## If upstream QLC+ changes

QLC+ is actively developed. If its CMake options, Qt module requirements, plugins, or output paths change, the environment may need a small update.

The kit deliberately avoids patching upstream source files so it remains easy to merge/rebase the official repository into your fork.
